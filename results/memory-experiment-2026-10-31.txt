Findings
- Offered but optional, the model never searched memory: a one-line bug doesn't need it. The tool's description
  alone added ~15% per run (sent with every request) for no benefit.
- Made mandatory, memory still saved no steps: the model read both files anyway (as the notes tell it to), so
  the search was one extra turn: +90% cost per run.
- A misleading note proposing price - quantity for this exact failure was read in 5/5 runs and applied in 0/5:
  the model verified against the code and the tests decided. Read-only notes + test-gated completion held.
- Memory rot showed up at once: the "memory, optional" arm wrote 5 identical notes (results/notes-orchard.jsonl).
  Fixed afterwards: a repeated fix now confirms the existing note (confirmed_by) instead of adding a copy.
- Limit: the task is too easy to show memory paying off. That needs repeated, harder failures where reading
  the code is expensive; lesson 14/30 (eval-driven development) is where a harder task set comes in.
